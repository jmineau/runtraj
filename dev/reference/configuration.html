Configuration#

config.yaml is blocks, each a field of ProjectConfig:

mets:
  hrrr: /path/to/hrrr_arl
models:
  hysplit: {n_hours: -24, numpar: 200}
variants:
  hrrr: {}
  hrrr-long: {n_hours: -72}
execution:
  backend: local
output: output

mets names the meteorology (for HYSPLIT, MetConfig). models names the transport models, each block with that model’s settings (HysplitConfig for hysplit). stages names what is made from each simulation’s particles after the model runs, each block with the import path of its stage’s class and then the stage’s settings. A stage’s block is named for its stage, which is also the name of its folder in the output directory and of its column in project.status(). Without a stages block, a project makes particles only. variants says what runs, and execution where (ExecutionConfig). Each class lives next to the code that uses it (runtraj.execution.config, runtraj.models.hysplit).

No setting sits at the top level. One written there is refused with a message that names its block, such as 'n_hours' is a hysplit setting. Write it under models: hysplit:. A key may be written once in each block: YAML would keep the last of two, so runtraj refuses the file and names the line of the second. Each page below lists its fields with their defaults and is generated from the code.

Every key#

These tables are generated from the code, so they always match the installed version.

Top level#

The blocks, and where the results go.

Parameter

Description

Default

mets

Meteorology by name, such as hrrr: the folder of its files, or a mapping of its settings. At least one is required. Each is checked by the met config of the transport model that reads it (runtraj.models.hysplit.MetConfig for HYSPLIT).

{}

models

Transport models by name, each a block of its settings: the defaults of every variant that runs it. A block named hysplit is that built-in model. Any other model class gets a block of any name that gives its import path as class, such as class: mypkg.models.MyModel. A model has one block. Left out, the project runs HYSPLIT with its defaults.

{'hysplit': {}}

stages

What is made from each simulation’s results after the transport model runs, by name, each a block that gives the stage’s import path as class and then its settings. A block is named for its stage: PYSTILT’s footprint, for example, is the block footprint with class: stilt.footprint.FootprintStage. A stage runs for every variant, unless the variant sets it to null. Left out, the project makes particles only.

{}

variants

Variants by name, each a set of overrides of the defaults. A variant’s own keys are met (needed with several mets unless the variant has a met’s name), model (the name of its models block, needed with several), realizations (run N times, realization k with seed + k, as one ensemble), and stages (a stage’s settings to change, by the stage’s name, or null for a variant without it). Every other key is a setting of its model. Variants with the same transport settings share one transport model run and differ in what their stages make from it. At least one is required: hrrr: {} runs the defaults.

{}

execution

Where the releases run and with what resources, such as backend: slurm and its options.

ExecutionConfig(backend='local', local=LocalConfig(cpus=1, fetch=True), slurm=SlurmCo...

output

Directory the results go to, relative to the project directory unless absolute. A URL such as s3://bucket/output puts it on an object store. Several projects can name the same directory and share runs.

'output'

HYSPLIT#

The keys of the hysplit block under models:, the transport model’s settings (HYSPLIT Integration). They are the defaults of every variant that runs HYSPLIT, and a variant may override any of them by writing the key itself. Left out, the block is HYSPLIT with the defaults below, which are HYSPLIT’s own. n_hours has no default, and capemin, kblt, kmixd, krand and vscales are unset unless given: HYSPLIT chooses them when it runs.

Parameter

Description

Default

n_hours

Length of each simulation, in hours. Negative runs backward in time. It has no default: a config must say it.

Required

seed

Random seed for a reproducible run. Different seeds give different runs. Requires krand: 2. HYSPLIT 5.1.0 ignores the seed under krand 4 and 10 to 13, and under 1 uses it only for the initial turbulent velocity. runtraj writes it to SETUP.CFG as -(abs(seed) + 1), because HYSPLIT reseeds its generator only from a negative value and gives every SEED of 0 or more the same stream. Realization k of a variant runs with seed + k, so realization 0 shares the unperturbed run’s seed.

None

numpar

Number of particles released per simulation. More particles sample the turbulence better and take longer to run.

2500

directory

The HYSPLIT folder as unpacked: runtraj runs exec/hycs_std under it and reads the data tables (ASCDATA.CFG, LANDUSE.ASC, ROUGLEN.ASC, TERRAIN.ASC) from its bdyfiles/. Unset, the first hycs_std on PATH runs, with the tables of a bdyfiles/ folder beside its folder; runtraj includes neither. The SHA-256 of hycs_std and of each table is part of each run’s settings, so runs of different builds are kept apart.

None

varsiwant

Particle variables hycs_std writes to the trajectory output, by the lowercase four-letter names HYSPLIT reads. Each is a column of the particles under the same name, except indx, time, long, and lati. zcfx is the vertical displacement by convective flux along the trajectory, in m. The default is HYSPLIT’s own list of 20.

['time', 'indx', 'long', 'lati', 'zagl', 'sigw', 'tlgr', 'zsfc', 'temp', 'samt', 'foo...

capemin

Convection option. -1 turns convection off, -2 uses the Grell scheme, and a positive value mixes vertically when CAPE exceeds it, in J/kg. Unset, HYSPLIT chooses -2 with ICHEM=8.

None

emisshrs

Duration of the particle release, in hours.

0.01

hscale

Horizontal Lagrangian timescale, in seconds.

10800.0

k10m

Use the 10 m winds and 2 m temperature as the lowest meteorology level (1) or skip them (0).

1

kbls

Derive boundary-layer stability from surface fluxes (1) or from wind and temperature profiles (2).

1

kblt

Boundary-layer turbulence scheme: 1 Beljaars, 2 Kantha-Clayson, 3 TKE, 4 measured variances, 5 Hanna. Unset, HYSPLIT chooses 5 with ICHEM=8.

None

kdef

Horizontal turbulence from vertical mixing (0) or wind deformation (1).

0

kmix0

Minimum mixed-layer depth, in meters.

150

kmixd

Mixed-layer depth source: 0 from the meteorology, 1 from the temperature profile, 2 from the TKE profile, 3 from a modified Richardson number. Unset, HYSPLIT chooses 3 with ICHEM=8.

None

krand

How HYSPLIT draws the random numbers for turbulence. 0, or unset, picks 2 when numpar is 5000 or less and 1 otherwise. 1 uses a precomputed table. 2 draws them during the run and is the only mode that uses seed. 3 uses no random numbers (a diagnostic mode). 4 draws them during the run from a clock-based seed, so every run differs; there are about 5000 possible seeds. 10 to 13 are modes 0 to 3 with a random initial seed. HYSPLIT does not check this value and other values silently break the turbulence, so runtraj rejects them.

None

kzmix

Vertical mixing adjustment: 0 none, 1 a single PBL-average value, 2 scale by tvmix.

0

maxpar

Maximum number of particles in a simulation. Unset gives every release location its full share: numpar for one location, n \* (numpar // n + 1) for n. A set value that stops a multipoint release before its last location fails the run.

None

mgmin

Minimum meteorological subgrid size, in grid points.

10

nturb

Turbulence on (0) or off (1).

0

outdt

Interval between particle outputs in the particle file, in minutes. 0 writes every time step. HYSPLIT writes no particles for a negative value, so it is refused. Only at 0 does runtraj check where the particles of a run that stopped early ended, to tell met that ran out from particles that left the met’s domain.

0

qcycle

Emission cycling period, in hours. 0 turns cycling off.

0.0

tkerd

Ratio w’²/(u’²+v’²) of TKE components when unstable.

0.18

tkern

Ratio w’²/(u’²+v’²) of TKE components when stable.

0.18

tlfrac

Fraction of the vertical Lagrangian timescale used as the time step of the dispersion scheme.

0.1

tvmix

Vertical mixing scale factor, used by the kzmix scaling modes.

1.0

veght

Height below which HYSPLIT counts a particle’s time toward its foot: the depth surface fluxes are mixed through. A value of 1 or less is a fraction of the mixed-layer height; a larger value is meters above ground.

0.5

vscale

Vertical Lagrangian timescale, in seconds.

200.0

vscaleu

Vertical Lagrangian timescale in an unstable boundary layer, in seconds.

200.0

vscales

Vertical Lagrangian timescale in a stable boundary layer, in seconds. -1 uses the Hanna timescale, which varies with the turbulence, and then vscaleu is not used. Unset, HYSPLIT chooses -1 with ICHEM=8.

None

w_option

Vertical motion method: 0 the meteorology’s vertical velocity, 1 isobaric, 2 isentropic, 3 constant density, 4 constant sigma.

0

wbbh

Height at which the fixed vertical velocity switches from rise to fall, in meters. Used by vertical motion option 9.

0.0

wbwf

Fixed fall velocity, in m/s. Used by vertical motion options 9 and 10.

0.0

wbwr

Fixed rise velocity, in m/s. Used by vertical motion option 9.

0.0

wvert

Interpolate WRF fields vertically with the WRF scheme instead of HYSPLIT’s.

True

z_top

Top of HYSPLIT’s computational domain, in meters above ground.

25000.0

ziscale

Factor applied to the mixed-layer height, written to HYSPLIT’s ZICONTROL file. 1.0 leaves it unscaled. A single value applies to every hour of the run. A list gives one factor per hour from the release (at most 150), and later hours are unscaled. HYSPLIT applies kmix0 after the factor, so the mixed layer never drops below kmix0. A negative value uses the meteorology’s own PBL height where the met files carry one.

1.0

siguverr

Standard deviation of the horizontal wind error, in m/s.

None

tluverr

Correlation timescale of the horizontal wind error, in minutes.

None

zcoruverr

Vertical correlation length of the horizontal wind error, in meters.

None

horcoruverr

Horizontal correlation length of the horizontal wind error, in km.

None

sigzierr

Standard deviation of the mixed-layer height error, in percent.

None

tlzierr

Correlation timescale of the mixed-layer height error, in minutes.

None

horcorzierr

Horizontal correlation length of the mixed-layer height error, in km.

None

A model in another package gets a block of any name that gives the model class’s import path as class, then that model’s own settings:

models:
  hysplit: {n_hours: -24}
  mine: {class: mypkg.models.MyModel, n_hours: -24}
variants:
  hrrr: {model: hysplit}
  hrrr-mine: {model: mine, met: hrrr}

With two or more models, each variant names its own with model. A model has one block: a second set of settings for it is a second variant.

A stage#

A stage’s block under stages: gives the import path of the stage’s class as class, then that stage’s own settings, which are the defaults of every variant. A variant changes some under its own stages key, under the stage’s name, and sets the stage to null to go without it. PYSTILT’s footprint is such a stage:

stages:
  footprint:
    class: stilt.footprint.FootprintStage
    grid: {xmin: -113.0, xmax: -110.5, ymin: 40.0, ymax: 42.0, xres: 0.01, yres: 0.01}
variants:
  hrrr: {}
  hrrr-coarse: {stages: {footprint: {grid: {xres: 0.05, yres: 0.05}}}}
  hrrr-particles: {stages: {footprint: null}}

The keys of one entry under mets:, for HYSPLIT (Meteorology).

Parameter

Description

Default

Directory holding the ARL meteorology files. Downloads are saved here. In a project, a relative path starts from the project directory; ~ and $VARIABLES are expanded.

Required

subgrid_dir

Directory for the cropped files, shared by every simulation that uses this meteorology. Each crop box gets its own folder inside it. Required when cropping your own files; not used with download, which crops files as it downloads them. A relative path starts from the project directory.

None

Name of a NOAA ARL archive to download files from with arlmet, such as hrrr, nam12, gdas1, or gfs0p25. Options for the archive (such as domain: ak) go in the same entry.

Server to download from: s3, ftp, or http.

Crop the meteorology to subgrid_bounds before running.

False

Longitude/latitude box to crop the meteorology to. Particles that leave it stop, so make it wide enough for the whole run.

None

subgrid_levels

Number of vertical levels to keep, counted from the surface. Unset keeps all.

None

Keep every run’s workdir, as the transport model left it, under scratch/ in the output directory. A failed run’s is always kept.

Grids#

A Grid is a rectilinear raster: a met’s crop box is a Bounds, and a stage that sums particles onto cells takes a Grid. Longitudes count modulo 360, so a grid across 180° can be written xmin: 170, xmax: 190 or xmin: 170, xmax: -170. An xmax west of xmin is read as crossing 180° when the two are on either side of 0° or one is written past 180°: with both in one hemisphere (xmin: -110.5, xmax: -113) they are taken to be swapped and the grid is refused. A grid spans at most 360°. Projected grids (a crs such as EPSG:32612) keep their bounds in degrees and take xres and yres in the projection’s units. A grid of more than a billion cells is refused, which catches a resolution in degrees on a grid in meters.

Config objects#

A config is what you write. project.variants turns each declared variant into a runtraj.config.Variant: its transport settings checked by the model’s config class, and what the file alone does not say, such as the transport model build. A variant with realizations: N stays one variant.

The RUNTRAJ_COMPUTE_ROOT environment variable sets the compute root, where each run’s workdir is made. It never changes a result, and projects can share one.

Parameters#

The settings that shape a run’s particles belong to the transport model, and are written in its block under models: (hysplit when the config has no models). HYSPLIT’s are in runtraj.models.hysplit.HysplitConfig, under HYSPLIT’s names (see HYSPLIT Integration). Each model’s block holds all of its settings, the ones runtraj reads itself among them (n_hours and seed): nothing passes from one model’s block to another’s. What a stage does with the particles afterwards is in the stage’s block, and does not change the particles or their settings folder.
