Configuration#

config.yaml is blocks, each a field of ProjectConfig:

mets:
  hrrr: /path/to/hrrr_arl
models:
  hysplit: {n_hours: -24, numpar: 200}
variants:
  hrrr: {}
  hrrr-long: {n_hours: -72}
execution:
  backend: local
output: output

mets names the meteorology (for HYSPLIT, HysplitMetConfig). models names the transport models, each block with that model’s settings (HysplitConfig for hysplit). stages names what is made from each simulation’s particles after the model runs, each block with the import path of its stage’s class and then the stage’s settings. A stage’s block is named for its stage, which is also the name of its folder in the output directory and of its column in project.status(). Without a stages block, a project makes particles only. variants says what runs, and execution where (ExecutionConfig). Each class lives next to the code that uses it (runtraj.execution.config, runtraj.models.hysplit).

No setting sits at the top level. One written there is refused with a message that names its block, such as 'n_hours' is a hysplit setting. Write it under models: hysplit:. A key may be written once in each block: YAML would keep the last of two, so runtraj refuses the file and names the line of the second. Each page below lists its fields with their defaults and is generated from the code.

A config runs code#

A class in a model’s or a stage’s block, and a transform’s kind, name a Python object by its import path. runtraj imports that module and calls the object, which is how a project uses a model or a stage from any installed package. runtraj does not check what the path names: any installed module is imported and any callable is called, even by runtraj check. So treat a config.yaml as you would a Python script, and run one only if you would run a script from the same person.

A service that runs configs other people send should not pass their YAML to runtraj. Build the ProjectConfig yourself from the fields you allow, with the import paths you choose.

Every key#

These tables are generated from the code, so they always match the installed version.

Top level#

The blocks, and where the results go.

Parameter

Description

Default

mets

Meteorology by name, such as hrrr: the folder of its files, or a mapping of its settings. At least one is required. Each is checked by the met config of the transport model that reads it (runtraj.models.hysplit.HysplitMetConfig for HYSPLIT).

{}

models

Transport models by name, each a block of its settings: the defaults of every variant that runs it. At least one is required: runtraj has no default model. A block named for a model runtraj supports (runtraj.models.MODELS: hysplit or flexpart) is that model, and hysplit: {} runs HYSPLIT with its own defaults. Any other model class gets a block of any name that gives its import path as class, such as class: mypkg.models.MyModel. A model has one block.

{}

stages

What is made from each simulation’s results after the transport model runs, by name, each a block that gives the stage’s import path as class and then its settings. A block is named for its stage: PYSTILT’s footprint, for example, is the block footprint with class: stilt.footprint.FootprintStage. A stage runs for every variant, unless the variant sets it to null. Left out, the project makes particles only.

{}

variants

Variants by name, each a set of overrides of the defaults. A variant’s own keys are met (needed with several mets unless the variant has a met’s name), model (the name of its models block, needed with several), realizations (run N times, realization k with seed + k, as one ensemble), and stages (a stage’s settings to change, by the stage’s name, or null for a variant without it). Every other key is a setting of its model. Variants with the same transport settings share one transport model run and differ in what their stages make from it. At least one is required: hrrr: {} runs the defaults.

{}

execution

Where the releases run and with what resources, such as backend: slurm and its options.

ExecutionConfig(backend='local', local=LocalConfig(cpus=1, fetch=True), slurm=SlurmCo...

output

Directory the results go to, relative to the project directory unless absolute. A URL such as s3://bucket/output puts it on an object store. Several projects can name the same directory and share runs.

'output'

HYSPLIT#

The keys of the hysplit block under models:, the transport model’s settings (HYSPLIT Integration). They are the defaults of every variant that runs HYSPLIT, and a variant may override any of them by writing the key itself. Every key but n_hours has the default below, so a block may be as short as hysplit: {n_hours: -24}; n_hours has no default, and a config without it is refused. capemin, kblt, kmixd, krand and vscales are unset unless given: HYSPLIT chooses them when it runs.

Parameter

Description

Default

n_hours

Length of each simulation, in hours. Negative runs backward in time. It has no default: a config must say it.

Required

seed

Random seed for a reproducible run. Different seeds give different runs. Requires krand: 2. HYSPLIT 5.1.0 ignores the seed under krand 4 and 10 to 13, and under 1 uses it only for the initial turbulent velocity. HYSPLIT 5.0.x never seeds the random numbers of a column release or an ichem: 5 run, so the seed does not reach them there. Must be 0 or more: runtraj writes it to SETUP.CFG as -(seed + 1), because HYSPLIT reseeds its generator only from a negative value and gives every SEED of 0 or more the same stream, so a seed and its negative would give the same run. Realization k of a variant runs with seed + k, so realization 0 shares the unperturbed run’s seed.

None

mode

What HYSPLIT makes: particle, the particle table; concentration, grids of each pollutant’s concentration (grids and pollutants); or trajectory, the trajectory table, from HYSPLIT’s trajectory program hyts_std.

'particle'

pollutants

ichem

HYSPLIT’s ICHEM, which in mode: concentration changes what a run counts: 0 concentration (the default); 1 a grid for each release location; 2 pollutants that convert (conversions); 5 deposition of whole particles by probability; 6 mass divided by air density; 9 a lowest level that follows the mixed layer; 10 a grid for each emission cycle (qcycle). The particle mode is ICHEM=8, the only value it takes, and a trajectory run reads none.

The SHA-256 of hycs_std and of each table is part of each run’s settings, so runs of different builds are kept apart.

Boxes#

A Bounds is a longitude/latitude box, in degrees, such as a met’s crop box. Longitudes count modulo 360, so a box across 180° can be written xmin: 170, xmax: 190 or xmin: 170, xmax: -170, and a box 360° wide or more holds every longitude (Bounds.contains()).

Config objects#

A config is what you write. project.variants turns each declared variant into a runtraj.config.Variant: its transport settings checked by the model’s config class, and what the file alone does not say, such as the transport model build. A variant with realizations: N stays one variant.

The RUNTRAJ_COMPUTE_ROOT environment variable sets the compute root, where each run’s workdir is made. It never changes a result, and projects can share one.

Parameters#

The settings that shape a run’s particles belong to the transport model, and are written in its block under models: (hysplit when the config has no models). HYSPLIT’s are in runtraj.models.hysplit.HysplitConfig, under HYSPLIT’s names (see HYSPLIT Integration). Each model’s block holds all of its settings, the ones runtraj reads itself among them (n_hours and seed): nothing passes from one model’s block to another’s. What a stage does with the particles afterwards is in the stage’s block, and does not change the particles or their settings folder.
